    Legacy Modernization
    
          
    Converts a whole codebase to a target stack as a durable run. It reads the source first — frameworks, entry points, routes, data access — then designs the target architecture, groups the files into components, and prices the work before converting anything. Secrets are redacted before any model call, the output arrives as a real project (solution, project files, host, configuration) rather than loose source, and a run survives a restart: stopped at file 390, it resumes at 391.

    Things worth knowing before you switch
    
          
    
            Tool calling is mandatory. Every agent gets its structured output by forcing the
            model to call a JSON tool, so a provider that can't do that can't run a single review.
            Test sends exactly that kind of call and tells you whether one came back.
          
    
          
    
            Costs become estimates. Spend is priced from a per-model table; a model that isn't in
            it is priced with a default rate and flagged as estimated on the Usage screen. A free local
            endpoint will still show a non-zero figure.
          
    
          
    
            Prompt caching is Anthropic-only. Switching away loses it and multi-agent runs get
            more expensive per token; switching back restores it automatically.
          
    
          
    
            Latency compounds. Reviews send far larger prompts than the test does. If the test
            takes tens of seconds, a full review will take minutes — set a per-connection timeout to fail fast
            rather than waiting out the platform-wide one.
          
    
        
    
      
    

      
      
    
        
    
          
    Notifications
    
          
    Send a Red gate somewhere people already look. Slack, Teams, or
            your own receiver — one https webhook URL per channel, scoped to this project.
    
        
    

        
    
          
    Two things worth knowing before you add one
    
          
    
            The URL is a credential. Anyone holding a Slack or Teams
            incoming-webhook URL can post to that channel, so it is encrypted when stored and
            never shown again — not here, not over the API. You will see the host and the last
            four characters, which is enough to tell two channels apart. If you lose it, delete
            the channel and add it again.
          
    
          
    
            Delivery is queued, not instant-or-never. Each notification is
            written down before it is sent, retried up to five times, and given up on after
            that — with the reason recorded below. There is no job runner in this deployment,
            so a notification written seconds before a restart is late rather than
            lost: it goes out on the next start, or the next time you open this page.
          
    
          
    
            Send a test as soon as you add a channel. It is the only way to find out that a
            URL is wrong before something actually goes Red.

    How to call any agent
    
          
    curl -X POST https://your-domain/api/v1/agents/code \
  -H "X-API-Key: lmsdlc_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "github_pr_url": "https://github.com/owner/repo/pull/88",
    "project_name": "My Project",
    "post_back": true
  }'
    
          
    
            Every response includes X-RateLimit-Limit-Minute, X-RateLimit-Remaining-Minute,
            X-RateLimit-Limit-Day and X-RateLimit-Remaining-Day headers.
            Exceeding a key's quota returns 429 with a Retry-After header.
          
    
          
    
            Bring your own LLM: teams can route calls through their own Anthropic or
            OpenAI-compatible credentials via PUT /api/v1/llm-config (X-API-Key auth), or
            override a single call with llm_provider / llm_api_key /
            llm_base_url / llm_model fields on any agent request.
